# 公开模型权重获取验证：LaBraM Base 与 EEGPT

核验日期：2026-09-09（Asia/Shanghai）

## 范围与方法

本备忘录只核验首期公开 EEG foundation model 多任务迁移评测所需的两份官方 checkpoint 获取链路。未下载完整权重、未安装依赖、未租用算力，也未对模型训练耗时或可复现性作推断。

HTTP 核验采用两种低流量方法：能正确处理 `HEAD` 的端点只发 `HEAD`；不支持 `HEAD` 的短时签名对象地址发 `Range: bytes=0-0`，实际只返回 1 字节。响应码、总大小和文件名均来自 2026-09-09 的现场响应，链接及可访问性以后可能变化。

## 1. LaBraM Base

### 官方来源与实际下载链路

[LaBraM 官方仓库](https://github.com/935963004/LaBraM)的 `checkpoints` 目录直接包含 `labram-base.pth`；GitHub 文件页显示约 92.1 MB，并提供 Raw 操作。文件页给出的地址是：

```text
https://github.com/935963004/LaBraM/raw/refs/heads/main/checkpoints/labram-base.pth
```

2026-09-09 15:55（北京时间）执行匿名 `HEAD -L`，观测到：

```text
HTTP/2 302
location: https://raw.githubusercontent.com/935963004/LaBraM/refs/heads/main/checkpoints/labram-base.pth

HTTP/2 200
content-type: application/octet-stream
accept-ranges: bytes
content-length: 96612769
etag: "5af5bf6bdcaea7e9fe33505455a4a259c382653e443894e7056947094d757562"
```

因此该文件在本次核验时可匿名读取，精确总大小为 96,612,769 字节。第一次直接请求 `raw.githubusercontent.com/.../main/...` 曾在 30 秒内无响应；改用 GitHub 文件页实际提供的 `/raw/refs/heads/main/` 地址后正常完成。这说明下载脚本应从仓库文件页给出的 Raw 地址开始并允许重定向，不能把单次 CDN 超时写成“权重失效”。

### 许可边界

仓库根目录的 [LICENSE](https://github.com/935963004/LaBraM/blob/main/LICENSE) 是 MIT License，版权行为 Weibang Jiang（2024），并允许在保留版权与许可通知的条件下使用、复制、修改和分发“Software”。checkpoint 与 LICENSE 同处一个仓库，且本次未发现 checkpoint 旁另有许可、用途限制或排除声明。

这构成“仓库发布者可能意图让根许可覆盖仓库内容”的较强迹象，但并非专门针对模型权重的明文授权。可执行做法是：内部评测可把来源 URL、获取日期、仓库 LICENSE 和文件哈希一起入账；若 BCI Arena 要镜像或向用户重新分发权重，发布前向维护者确认根 MIT 是否明确覆盖 `*.pth`，并保留书面答复。网站可以链接官方 Raw 文件，不应把“公开可下载”表述成“权重许可已经完全清除”。

## 2. EEGPT

### 官方来源与实际下载链路

[EEGPT 官方仓库 README](https://github.com/BINE022/EEGPT#pretrained-models)写明可从 Figshare 下载 `EEG_large`，目标文件位于 `Files/EEGPT/checkpoint/eegpt_mcae_58chs_4s_large4E.ckpt`，并要求下游任务把它保存为 `checkpoint/eegpt_mcae_58chs_4s_large4E.ckpt`。README 的实际链接是：

```text
https://figshare.com/s/e37df4f8a907a866df4b
```

该 URL 是 Figshare private-link 分享，不是要求申请权限的登录页。公开索引中的同名文件指针给出了 `file=46452745`；随后用 Figshare 官方文档规定的下载格式和官方 README 中的分享令牌进行交叉验证：

```text
https://ndownloader.figshare.com/files/46452745?private_link=e37df4f8a907a866df4b
```

这个入口现场返回的 `Content-Disposition` 文件名与官方 README 指定的 checkpoint 完全一致。2026-09-09 15:58（北京时间）的 1 字节 Range 响应为：

```text
HTTP/2 302
content-disposition: attachment;filename=eegpt_mcae_58chs_4s_large4E.ckpt
location: https://s3-eu-west-1.amazonaws.com/...（10 秒有效的签名 URL）

HTTP/1.1 206 Partial Content
Content-Range: bytes 0-0/1020602524
Content-Length: 1
Content-Disposition: attachment; filename="eegpt_mcae_58chs_4s_large4E.ckpt"
Last-Modified: Tue, 21 May 2024 08:45:36 GMT
ETag: "a165305f329f51b57691c8a3131f9b79"
```

总大小因此是 1,020,602,524 字节。只把 `file_id` 请求到 downloader、但不携带 README 分享 URL 中的 `private_link` 时，现场得到 `403` 和 `{"message":"Insufficient permissions"}`；携带该公开分享令牌后无需账号即可取得 206。脚本应每次从 downloader 入口重新获取短时 S3 地址，不应缓存或发布含 `X-Amz-Signature` 的临时 URL。

另外，普通浏览页的 `HEAD` 在现场返回 AWS WAF `202` challenge，Web 抓取器访问分享页也出现 `403`；而按 Figshare [私有文件下载文档](https://docs.figshare.com/old_docs/api/articles/#download-private-files)附带 `private_link` 后，1 字节 Range 实际成功。这里应记录为页面防自动化和 HTTP 方法差异，不能据此宣称文件损坏或必须登录。

### 许可边界

GitHub 仓库根目录的 [LICENSE](https://github.com/BINE022/EEGPT/blob/main/LICENSE) 是 Apache License 2.0；README 也把 GitHub 仓库称为官方实现。但权重没有放在该仓库中，而是放在独立的 Figshare private-link 对象中。README 只说“可以下载预训练模型”，没有把 Apache-2.0 明确附到 checkpoint，也没有在下载说明旁给出独立模型许可。由于分享页面被 WAF challenge，本次未能从该对象取得可核验的 Figshare license 字段。

因此应把两项分开记录：

- **代码**：Apache-2.0 明确，使用和分发时按其 LICENSE/NOTICE 要求办理。
- **权重**：技术上匿名可取，但本次证据不足以断言 Apache-2.0 覆盖该 `.ckpt`。在内部可复现实验中记录出处与不确定性；在 BCI Arena 镜像、打包或商业再分发前，向作者取得权重许可或找到带明确许可字段的正式发布页。网站当前只链接官方分享页，并写“权重许可：待作者/发布页确认”。

## 3. 对首期 benchmark 的直接影响

1. **技术获取不是首期阻塞项。** 两份权重在本次都能以匿名 HTTP 链路读取；LaBraM Base 约 92 MiB，EEGPT 约 973 MiB。后者要在自动化脚本中保留 `private_link` 参数并立即跟随短时重定向。
2. **把“可下载”和“可再分发”做成两个字段。** 榜单的模型卡至少展示官方来源、checkpoint 文件名、获取日期、字节数、完整下载后的 SHA-256、代码许可、权重许可与证据 URL。
3. **首次完整拉取后再做内容校验。** 本次没有下载大文件，无法计算 SHA-256，也没有测试 `torch.load`。正式 calibration 应在获准的完整下载后计算哈希、检查 checkpoint 键和所需预处理配置；这一步才能判断“文件可用”，HTTP 可读只证明获取链路成立。
4. **不镜像许可不明确的 EEGPT 权重。** 首期 CI 可由受控 runner 从官方分享入口取文件并进入私有缓存；公开页面只发布结果和来源链接。若缓存/构件会被公众下载，就等同于再分发，应先解决许可文本。
5. **存储规划以数据集为主。** 两份 checkpoint 合计约 1.12 GB，不是现有 `/home` 仅余 206 GiB 的主要压力；公开 EEG 数据集、预处理缓存和多折中间产物才可能迅速超过现有余量。先用小数据做 calibration，完整 TUEG 等大数据应放独立存储，不要直接灌入当前 `/home`。

## 4. 证据强度与未完成项

- 已直接核验：官方仓库身份、README/目录中的 checkpoint 名、仓库 LICENSE、LaBraM 精确 HTTP 大小、EEGPT 精确 Range 总大小、EEGPT 分享令牌有无时的访问差异。
- 尚未核验：完整文件哈希、权重能否被框架成功加载、作者是否另有 checkpoint 专属许可、Figshare 对象的元数据许可字段。
- 本文不构成法律意见，也不声称商标、版权或模型权重许可已经清除；它给出的是可复查的技术证据和发布前待办。
